# หลังบ้านสำหรับแอดมิน (Admin back office) — เอกสารออกแบบ

วันที่: 2026-09-03
สถานะ: อนุมัติแล้ว (ผู้ใช้ยืนยัน 2026-09-03)

## 1. เป้าหมาย

เพิ่มหน้าหลังบ้านที่ `/admin` ให้แอดมินคนเดียว (เจ้าของโปรเจกต์) จัดการสิ่งที่ตอนนี้ต้องแก้ในโค้ด
ได้แก่ กุญแจและโมเดล AI, คลังเอกสาร PDF, สถิติการใช้งาน และกฎเงื่อนไขของแบบประกัน

เว็บคำนวณเบี้ยที่หน้าแรกยังเปิดสาธารณะเหมือนเดิม ใครมีลิงก์ก็ใช้ได้ทันที ไม่มีล็อกอิน

## 2. ขอบเขต

### อยู่ในขอบเขต
- ล็อกอินด้วย Google ผ่าน Supabase Auth จำกัดเฉพาะอีเมลในรายชื่อแอดมิน
- หน้า `/admin/ai` — กุญแจ 5 ค่าย, เปิดปิดโมเดล, โมเดลเริ่มต้น, งบต่อเดือน
- หน้า `/admin/knowledge` — อัปโหลด/ปิดใช้งาน/ลบเอกสาร PDF
- หน้า `/admin/usage` — จำนวนการคำนวณ, แบบที่ถูกใช้บ่อย, ค่าใช้จ่าย AI รายเดือน
- หน้า `/admin/rules` — ดูและแก้กฎเงื่อนไข พร้อมประวัติการแก้และปุ่มคืนค่าเดิม
- บันทึกการคำนวณจากหน้าเว็บสาธารณะ เพื่อให้หน้าสถิติมีข้อมูล

### นอกขอบเขต (เฟสถัดไป)
- ตัวอ่านไฟล์ Excel บนเว็บ (ข้อ C ที่ผู้ใช้ตัดออก) — ยังแปลงด้วยสคริปต์ Python บนเครื่อง
- ตัว AI ถามตอบเอง, LINE, Facebook, n8n
- บัญชีผู้ใช้สำหรับตัวแทนหรือลูกค้า

## 3. สถาปัตยกรรม

```
เบราว์เซอร์ (สาธารณะ)            เบราว์เซอร์ (แอดมิน)
   หน้าคำนวณ  ── บันทึกสถิติ ──►  /admin/*  ──► Supabase Auth (Google)
        │                              │
        └──────────► Next.js Route Handlers (ฝั่งเซิร์ฟเวอร์เท่านั้น)
                              │
                              ├─► Supabase service role → ตารางเดิม (public.*)
                              └─► Supabase service role → ตารางใหม่ (ins.*)
```

- **โปรเจกต์ Supabase:** DATA2.0 ref `tmbbxahyxwkshxuxphcb` (มีระบบอื่นใช้อยู่แล้ว)
- **ตารางเดิมที่ใช้ร่วม (ห้ามแก้โครงสร้างหรือ RLS):** `public.api_keys`, `public.model_configs`,
  `public.app_settings`, `public.usage_ledger`, `public.profiles`
- **ตารางใหม่ ทั้งหมดอยู่ใน schema `ins`:** `ins.admins`, `ins.knowledge_docs`,
  `ins.plan_rule_overrides`, `ins.rule_audit`, `ins.quote_events`
- กุญแจ AI ใช้ชุดของแอดมินเป็นของกลาง (`api_keys.owner_id` = uuid ของแอดมิน) เพราะผู้ใช้ทั่วไป
  ไม่มีบัญชี ค่าใช้จ่ายทั้งหมดจึงรวมอยู่ที่เดียว
- ทุกการอ่านเขียนฐานข้อมูลทำในฝั่งเซิร์ฟเวอร์ กุญแจบริการไม่ถูกส่งไปเบราว์เซอร์

## 4. การล็อกอินและสิทธิ์

1. `/admin` แสดงปุ่มเดียว "เข้าสู่ระบบด้วย Google" ใช้ Supabase Auth
2. หลังกลับจาก Google ระบบตรวจอีเมลกับ `ins.admins` ถ้าไม่มีจะขึ้นข้อความว่าไม่มีสิทธิ์
3. ตาราง `ins.*` เปิด RLS โดยอนุญาตเฉพาะผู้ใช้ที่อีเมลอยู่ใน `ins.admins`
4. **ไม่แก้ `public.profiles.role` ของใคร** แอดมินของแอปนี้แยกจากแอดมินของระบบเดิม

## 5. ตารางใหม่ (schema `ins`)

| ตาราง | หน้าที่ | คอลัมน์หลัก |
|---|---|---|
| `admins` | รายชื่ออีเมลที่เข้าหลังบ้านได้ | `email` (pk), `note`, `created_at` |
| `knowledge_docs` | เอกสาร PDF ในคลังความรู้ | `id`, `title`, `plan_code`, `storage_path`, `bytes`, `page_count`, `raw_text`, `status`, `is_active`, `created_at` |
| `plan_rule_overrides` | กฎที่แอดมินแก้ ทับไฟล์ในโค้ด | `plan_code` (pk), `rules` jsonb, `updated_at`, `updated_by` |
| `rule_audit` | ประวัติการแก้กฎ | `id`, `plan_code`, `before` jsonb, `after` jsonb, `changed_by`, `created_at` |
| `quote_events` | บันทึกการคำนวณจากหน้าสาธารณะ | `id`, `plan_code`, `variant`, `age`, `sex`, `mode`, `rider_codes` text[], `total_modal` bigint, `created_at` |

`quote_events` ไม่เก็บชื่อ เบอร์โทร หรือข้อมูลระบุตัวลูกค้า เก็บเฉพาะพารามิเตอร์ที่ใช้คำนวณ

## 6. หน้าจอ

### `/admin/ai`
- ตารางกุญแจ 5 ค่าย แสดงเฉพาะ 4 ตัวท้าย มีปุ่มแทนที่และปุ่มทดสอบการเชื่อมต่อ
- รายการโมเดลจาก `model_configs` พร้อมสวิตช์เปิดปิดและราคา
- เลือกโมเดลเริ่มต้นและตั้งงบต่อเดือน เขียนลง `app_settings`

### `/admin/knowledge`
- อัปโหลด PDF หลายไฟล์พร้อมกัน เก็บใน Supabase Storage bucket `insurance-docs`
- ดึงข้อความจาก PDF เก็บใน `raw_text` เพื่อให้เฟส AI ใช้ค้นได้
- ตารางรายการ: ชื่อ, แบบประกันที่เกี่ยว, ขนาด, จำนวนหน้า, สถานะ, สวิตช์เปิดปิด, ปุ่มลบ

### `/admin/usage`
- การ์ดสรุป: จำนวนการคำนวณ 30 วัน, แบบที่ถูกใช้บ่อยสุด, ค่าใช้จ่าย AI เดือนนี้เทียบงบ
- กราฟแท่งรายวัน และตารางแยกตามแบบประกัน

### `/admin/rules`
- เลือกแบบประกัน แล้วแก้กฎเป็นฟอร์มตาราง: ช่วงอายุ, ทุนขั้นต่ำ/สูงสุด, กฎรวมของสัญญาเพิ่มเติม
- ค่าที่ต่างจากไฟล์ในโค้ดถูกทำเครื่องหมาย และมีปุ่มคืนค่าเดิมทีละรายการหรือทั้งแบบ
- ยืนยันก่อนบันทึกทุกครั้ง พร้อมสรุปว่าจะเปลี่ยนอะไรบ้าง แล้วบันทึกลง `rule_audit`

## 7. ผลต่อเว็บคำนวณ

- ตอนโหลดกฎ ระบบอ่านไฟล์ในโค้ดก่อน แล้วทับด้วย `plan_rule_overrides` ถ้ามี
- ถ้าต่อฐานข้อมูลไม่ได้ ใช้ไฟล์ในโค้ดต่อไป เว็บคำนวณต้องไม่ล่มเพราะฐานข้อมูล
- บันทึก `quote_events` แบบไม่รอผล ถ้าบันทึกไม่สำเร็จก็ไม่กระทบการคำนวณ

## 8. การทดสอบ

- กฎที่ถูกทับ: เทสว่าเครื่องคำนวณใช้ค่าใหม่จริง และคืนค่าเดิมได้
- สิทธิ์: อีเมลนอกรายชื่อเข้าหลังบ้านไม่ได้ และเรียก API ตรง ๆ ก็ถูกปฏิเสธ
- กุญแจ AI: ตรวจว่าค่าเต็มไม่เคยถูกส่งกลับไปเบราว์เซอร์
- ชุดเทสเดิม 242 ข้อต้องยังผ่านทั้งหมด

## 9. สิ่งที่ผู้ใช้ต้องทำ

- เปิด Google provider ใน Supabase (ทำแล้ว 2026-09-03)
- ให้อีเมลที่จะเป็นแอดมิน เพื่อใส่ใน `ins.admins`
