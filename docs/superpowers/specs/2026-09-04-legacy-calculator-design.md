# เครื่องคำนวณมรดกเพื่อครอบครัว สำหรับลูกค้า — เอกสารออกแบบ

วันที่: 2026-09-04
สถานะ: รอผู้ใช้ตรวจทาน

## 1. เป้าหมาย

หน้า `/` คือเครื่องคำนวณของตัวแทน: เลือกแบบประกันได้ทุกแบบ ติ๊กสัญญาเพิ่มเติมได้ทุกตัว เห็นคำเตือนภาษาช่าง
ลูกค้าที่กดแอดเข้ามาไม่ต้องการสิ่งเหล่านั้น เขาต้องการคำตอบเดียวภายในไม่กี่วินาที: **"ถ้าฉันอยากให้ครอบครัวได้ X ล้าน ฉันต้องจ่ายเท่าไหร่"**

เอกสารนี้ออกแบบ **เครื่องคำนวณสำหรับลูกค้า** ที่ขายชุด "มรดกเพื่อครอบครัว" เพียงชุดเดียว
ลูกค้าเลื่อนเลือกวงเงิน กรอกอายุ เลือกเพศ → เห็นเบี้ยและผลประโยชน์ทันที → กดทักตัวแทนได้พร้อมข้อมูลที่กรอกไว้แล้ว

เครื่องคำนวณนี้เป็นชิ้นแรกของเซลล์เพจ `/legacy` เนื้อหาขาย (พาดหัว 3 ความจริง จุดต่าง FAQ) จะมาห่อรอบมันในงานถัดไป

## 2. ขอบเขต

### อยู่ในขอบเขต
- หน้าใหม่ `/legacy` ที่ตอนนี้มีเครื่องคำนวณอย่างเดียว
- คอมโพเนนต์ `LegacyCalculator` ที่นำไปวางในเซลล์เพจได้โดยไม่ต้องแก้
- ปุ่มทัก 3 ทาง (LINE, Messenger, แชท AI ในระบบ) ที่แนบวงเงิน อายุ เพศ และเบี้ยไปกับข้อความ
- จัดการ 3 กรณีที่ราคาไม่ควรปรากฏ (ข้อ 6)
- ช่อง `?q=` ในหน้า `/chat` เพื่อรับข้อความที่เตรียมไว้จากปุ่ม "ถาม AI"

### นอกขอบเขต
- เนื้อหาขายของเซลล์เพจ — งานถัดไป ใช้สเปกแยก
- เก็บลีดลงฐานข้อมูล — ลูกค้าไม่ต้องกรอกอะไรที่ระบุตัวตน
- แก้หน้า `/` ของตัวแทน — ไม่แตะแม้แต่บรรทัดเดียว
- แสดงเบี้ยปีถัด ๆ ไป — ตารางเบี้ยในระบบมีเรต DCI รายอายุแต่ยังไม่ได้ยืนยันกับโบรชัวร์ว่าเป็นสัญญาต่ออายุรายปี จึงแสดงเฉพาะเบี้ยปีแรกและกำกับไว้ให้ชัด

## 3. สิ่งที่ยกมาจากของเดิม

ตรรกะทั้งหมดมีอยู่แล้วและมีเทสต์ครอบอยู่แล้ว หน้าใหม่เรียกใช้โดยไม่แก้:

| ของเดิม | ใช้ทำอะไร |
|---|---|
| `getBundle("LEGACY_FAMILY")` | ชุดเดียวที่หน้านี้ขาย ล็อกไว้ในโค้ด |
| `bundleAgeRange(bundle)` | ช่วงอายุที่รับ (20–65) กำหนดขอบช่องอายุ |
| `bundleModePremiums(bundle, tier, { age, sex })` | เบี้ยรายปี / ราย 6 เดือน / รายเดือน ครบสามงวด |
| `quoteBundle(bundle, tier, who)` | `deathBenefit` (ก่อนและหลังอายุ 60) และ `meta.expired` |
| `describeTier(bundle, tier)` | ชื่อแผน "มรดก 3 ล้าน" ในข้อความทัก |
| `formatBaht(satang)` | ตัวเลขทุกตัวบนหน้า |

สิ่งที่ **ไม่** ยกมา: `PlanSelect`, `QuoteForm`, `RiderRow`, `QuoteResultPanel`, `WarningList`, `ShareToLineButton`, `summaryText`
ทั้งหมดออกแบบเพื่อตัวแทน มีตัวเลือกและคำเตือนที่ลูกค้าไม่ควรเห็น

## 4. หน้าตาและพฤติกรรม

จอมือถือคือจอหลัก คอลัมน์เดียว ตัวเลขเบี้ยใหญ่ที่สุดบนหน้า

### ช่องกรอก 3 ช่อง
- **วงเงินมรดก** — แถบเลื่อน 1 ถึง 10 ขั้นละ 1 ล้าน ตัวเลขที่เลือกโชว์ตัวใหญ่เหนือแถบ ("3,000,000 บาท") ค่าเริ่มต้น 1 ล้าน
- **อายุ** — ช่องกรอกตัวเลข (`inputmode="numeric"`) ค่าเริ่มต้นว่าง ไม่ใช่ 35 — ให้ลูกค้ากรอกเองเพื่อให้ตัวเลขที่เห็นเป็นของเขาจริง ๆ
- **เพศ** — สองปุ่มสลับ ชาย / หญิง ค่าเริ่มต้นชาย

ทุกช่องคำนวณใหม่ทันทีที่เปลี่ยน ไม่มีปุ่ม "คำนวณ"

### การ์ดผลลัพธ์ (เมื่อกรอกอายุครบ)
- **เบี้ยตัวใหญ่**: รายเดือน ถ้าบริษัทรับ ไม่งั้นรายปี (ข้อ 6 กรณี ข) ตามด้วยบรรทัด "ตกวันละ N บาท" (เบี้ยรายปี ÷ 365 ปัดขึ้นเป็นบาท)
- **งวดที่เหลือ** ตัวเล็กใต้ลงมา เฉพาะงวดที่รับได้ (ราย 6 เดือนรับได้เสมอ — ขั้นต่ำมีเฉพาะรายเดือน)
- **ครอบครัวได้รับ**: `deathBenefit.sumFrom` เช่น 3,000,000 บาท
- **ก่อนอายุ 60 ได้**: `deathBenefit.sumBefore` เช่น 3,150,000 บาท — แสดงเฉพาะเมื่อ `alreadyPastAge` เป็นเท็จ
- **บรรทัดกำกับ** (ตัวเล็ก แต่ต้องอยู่ในการ์ด ไม่ใช่ท้ายหน้า):
  "เบี้ยปีแรก ส่วนสัญญาโรคร้ายแรงคิดตามอายุ จึงปรับขึ้นในปีถัดไป · จ่ายเมื่อเสียชีวิต หรือเมื่อตรวจพบ 1 ใน 31 โรคร้ายแรงตามคำนิยามในกรมธรรม์"

### ปุ่มทัก
เรียงใต้การ์ด: **ทัก LINE**, **ทัก Messenger**, **ถาม AI ก่อนก็ได้**
ทุกปุ่มแนบข้อความเดียวกัน (ข้อ 5) และแสดงแม้ยังไม่ได้กรอกอายุ (ข้อความจะสั้นลง ไม่มีเบี้ย)
ปุ่ม LINE และ Messenger แสดงเฉพาะเมื่อตั้งค่าไว้ (ข้อ 7) ปุ่มถาม AI แสดงเสมอเพราะอยู่ในระบบเดียวกัน

## 5. ข้อความที่แนบไปกับปุ่ม

สร้างโดยฟังก์ชันเดียว `legacyMessage()` ใน `src/lib/legacy-cta.ts` เพื่อให้ทั้งสามช่องทางได้ข้อความตรงกันและเทสต์ได้

กรอกครบ:
```
สนใจมรดกเพื่อครอบครัว 3 ล้าน อายุ 38 ชาย เบี้ยประมาณ 1,501 บาท/เดือน
```
ยังไม่กรอกอายุ:
```
สนใจมรดกเพื่อครอบครัว 3 ล้าน
```
อายุอยู่นอกช่วงที่รับ:
```
สนใจมรดกเพื่อครอบครัว 3 ล้าน อายุ 68 หญิง ขอแบบที่เหมาะกับอายุนี้
```

เบี้ยที่ใส่ในข้อความคืองวดเดียวกับตัวใหญ่บนการ์ด

ลิงก์ที่สร้าง:
- LINE: `https://line.me/R/oaMessage/{OA_ID}/?{text}` — เปิดห้องแชทพร้อมข้อความในช่องพิมพ์ ลูกค้ากดส่งเอง
- Messenger: `https://m.me/{PAGE}?text={text}` — พฤติกรรมเดียวกันบนแอป Messenger (บนเว็บบางเบราว์เซอร์ไม่เติมข้อความ ลิงก์ยังเปิดแชทได้ ไม่พัง)
- แชท AI: `/chat?q={text}` — หน้าแชทเติมข้อความลงช่องพิมพ์ ลูกค้ากดส่งเอง ไม่ส่งอัตโนมัติ

## 6. กรณีที่ราคาต้องไม่ปรากฏ หรือปรากฏต่างไป

**ก. อายุนอกช่วง 20–65** (ช่องอายุยอมให้พิมพ์ได้ทุกค่าเพื่อไม่ให้ลูกค้าอายุ 68 รู้สึกว่าถูกกันออก)
การ์ดผลลัพธ์เปลี่ยนเป็นข้อความ: "ชุดนี้รับอายุ 20–65 ปี ทักมาให้เราช่วยหาแบบที่เหมาะกับคุณ" ปุ่มทักยังอยู่ครบ

**ข. งวดรายเดือนต่ำกว่าขั้นต่ำ 1,000 บาท** (`belowMinimum` ใน `ModePremium`) — เกิดกับคนอายุน้อยที่เลือกวงเงินต่ำ เช่น ชาย 35 ปี 1 ล้าน รายเดือน 540 บาท
งวดนั้นไม่แสดงเลย ตัวใหญ่ใช้รายปี (6,005 บาท/ปี) และบรรทัด "ตกวันละ 17 บาท" ทำหน้าที่ทำให้ตัวเลขจับต้องได้แทนรายเดือน
เหตุผลที่ไม่แสดง "≈ เดือนละ 500": มันอ่านเป็นการชำระรายเดือนที่บริษัทไม่รับ

**ค. ตารางเบี้ยหมดอายุ** (`meta.expired`, ปัจจุบัน 2027-03-31)
ซ่อนเบี้ยทุกตัว การ์ดแสดง "ขอราคาปัจจุบันได้ทางแชท" ปุ่มทักยังอยู่ และข้อความที่แนบไม่มีเบี้ย
ผลประโยชน์ (ครอบครัวได้รับ X) ยังแสดงได้ เพราะไม่ขึ้นกับตารางเบี้ย

**ง. ชุดคำนวณไม่ครบ** (`BUNDLE_INCOMPLETE`) — ในทางทฤษฎีเกิดไม่ได้เพราะช่วงอายุถูกกันไว้แล้วในข้อ ก แต่ถ้าเกิด ให้ปฏิบัติเหมือน ก

## 7. การตั้งค่า

สองค่าใหม่ใน `.env.example` อ่านฝั่งเบราว์เซอร์:
- `NEXT_PUBLIC_LINE_OA_ID` — เช่น `@abcd123`
- `NEXT_PUBLIC_FB_PAGE` — ชื่อหรือรหัสเพจที่ใช้ใน `m.me/…`

ค่าว่าง = ซ่อนปุ่มนั้น ผู้ใช้ยังไม่มีค่าเหล่านี้ตอนนี้ จึงจะได้เห็นหน้าที่มีเฉพาะปุ่มถาม AI จนกว่าจะเติม
