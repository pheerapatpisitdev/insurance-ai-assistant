# โครงหน้าใหม่: เมนูซ้ายทั้งเว็บ + หน้าภาพรวม

วันที่ 2026-09-17 · ตกลงกับเจ้าของระบบแล้ว

## ปัญหาที่แก้

เจ้าของระบบระบุสี่ข้อ:

1. สลับไปมาระหว่างหน้าคำนวณกับหลังบ้านลำบาก — เมนูอยู่คนละที่
2. ไม่รู้ว่ามีอะไรให้ใช้บ้าง — คนอื่นในทีมไม่รู้ว่าหน้าไหนทำอะไร
3. ไม่มีหน้าสรุปภาพรวม — เปิดมาแล้วไม่เห็นว่าวันนี้เป็นยังไง
4. ดูไม่เหมือนโปรแกรมจริงจัง

## ขอบเขต

เมนูซ้ายขึ้น **ทุกหน้า** รวมหน้าขายที่ลูกค้าเห็น ยกเว้น `/login`

เจ้าของระบบเลือกข้อนี้หลังได้รับแจ้งผลที่ตามมาแล้ว: ลูกค้าที่มาจากโฆษณาจะเห็นเมนู CRM, API,
โฆษณา และกดแล้วเด้งไปหน้าล็อกอิน เมนูนั้นบอกคนนอกด้วยว่าระบบหลังบ้านอยู่ตรงไหน หน้าเหล่านั้น
ล็อกอยู่และเข้าไม่ได้ แต่การมีอยู่ของมันเปิดเผย เจ้าของยืนยันเลือกข้อนี้

**ข้อยกเว้นเดียว** ปุ่มออกจากระบบแสดงเฉพาะเมื่อมี session จริง ปุ่มที่กดแล้วไม่มีความหมาย
เป็นความผิดพลาด ไม่ใช่ความชอบ

## สี

หน้าขายใช้สามธีมบนโครง `.theme-legacy` เดียวกัน — ดำทอง (lifeprotect, lifetreasure),
โรส (plb, legacy, ihealthy-ultra ผ่าน `satin-rose`), และ `ishield-scope`

`HomeButton` เขียนเตือนไว้แล้วว่าสีตรงๆ ที่เลือกให้สวยบนธีมหนึ่งจะมองไม่เห็นบนอีกธีม และเป็น
ความผิดพลาดที่โปรเจกต์นี้เคยเจอ เมนูจึงประกาศตัวแปรของตัวเอง — `--shell-bg`, `--shell-ink`,
`--shell-mute`, `--shell-line`, `--shell-active` — มีค่าเริ่มต้นเป็นธีมสว่าง แล้วให้
`.theme-legacy` และหน้าแชทกำหนดทับ ห้ามมีสีตรงๆ ในคอมโพเนนต์

**ต้องคำนวณค่า contrast ทุกธีมก่อน commit** ไม่ใช่ดูด้วยตา

## ข้อจำกัดทาง CSS ที่ต้องเคารพ

`globals.css` ให้ `.theme-legacy > *` มี `position: relative; z-index: 1` และกฎนั้นชนะ utility
class ของ Tailwind ด้วย specificity — องค์ประกอบที่ `fixed` จึงต้องห่อด้วย `<div className="relative">`
และวางไว้ **หลัง** เนื้อหา เหมือนที่ `HomeButton` ทำ ไม่งั้นจะกลายเป็นแถบเต็มความกว้างทับหน้า

## มือถือกับคอม

ใช้พอกันทั้งสอง

- **≥1024px** เมนูกางค้าง กว้าง 240px เนื้อหาเลื่อนเข้ามา
- **<1024px** เมนูซ่อน ปุ่มขีดสามขีดมุมซ้ายบน เปิดเป็นลิ้นชักทับหน้าจอพร้อมฉากหลังทึบ
  ปิดด้วยแตะฉากหลัง กด Esc หรือเลือกเมนู · โฟกัสคีย์บอร์ดวนอยู่ในลิ้นชักขณะเปิด

```
ช่องทาง
  Messenger       /admin/messenger
  โฆษณา           /admin/ads
  API             /admin/api

แบบประกัน

```

หน้าขายสร้างจากทะเบียนสินค้า ด้วยเหตุผลเดียวกับที่ `peopleIn` อ่านชื่อแบบประกันจากทะเบียน:
แบบประกันที่เพิ่มปีหน้าต้องปรากฏในวันที่เพิ่ม ไม่ใช่วันที่มีคนสังเกตว่าหาย

## หน้าภาพรวม

ตอนนี้ `/admin` เป็น redirect ห้าบรรทัดไป `/admin/ai` จะกลายเป็นหน้าจริง

**ส่วนบน — อะไรค้างรอคุณอยู่** แสดงเฉพาะข้อที่เป็นจริง ไม่มีก็ไม่ขึ้น

| สัญญาณ | อ่านจาก | ทำไมสำคัญ |
|---|---|---|
| ยังไม่ได้สมัครรับข้อความจากเพจ | `ins_channel_auth` + สถานะ subscribed | ข้อความลูกค้าไม่เข้าระบบเลย ค้างมาหลายวัน |
| โฆษณายังไม่จับคู่สินค้า | `ins_ad_products` ว่าง | ไม่รู้ว่าลูกค้ามาจากโฆษณาตัวไหน |
| คำถามที่ AI ตอบไม่ได้ | `ins_unanswered` 7 วันล่าสุด | จุดที่ระบบยังตอบไม่ได้ |
| ตารางเบี้ยใกล้หมดอายุ | `tablesMeta().expiresOn` | เตือนล่วงหน้า 60 วัน |
| ค่า AI ใกล้ชนงบเดือนนี้ | `ins_usage_ledger` เทียบ `monthly_budget_thb` | งบหมดแล้วผู้ช่วยปิดตัวเอง |

**ส่วนล่าง — ตัวเลข 7 วัน** ใช้ `loadCrm()` ที่มีอยู่แล้ว ไม่คำนวณซ้ำ

## ทดสอบ

- เมนูทุกลิงก์ชี้ไปหน้าที่มีจริง สร้างจากทะเบียน ไม่ใช่รายการมือ
- ปุ่มออกจากระบบไม่ขึ้นเมื่อไม่มี session และขึ้นเมื่อมี
- contrast ของ `--shell-*` ผ่านเกณฑ์ทุกธีม คำนวณในเทสต์
- หน้าภาพรวมไม่แสดงการเตือนที่ไม่เป็นจริง
- ตรวจด้วยเบราว์เซอร์จริงทั้งขนาดคอมและมือถือ อย่างน้อยหนึ่งหน้าขายต่อธีม

## สิ่งที่ไม่ทำ

- ไม่ย้าย `/other-plans` ลิงก์นี้ถูกส่งให้ลูกค้าแล้วทั้งจากแชทและจากบอท Messenger
- ไม่แตะเนื้อหาหน้าขาย เปลี่ยนเฉพาะโครงรอบนอก
- ไม่ทำเมนูที่เปลี่ยนตามคนดู เจ้าของเลือกให้เหมือนกันทุกคน
