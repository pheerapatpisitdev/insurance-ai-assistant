# เว็บแอปคำนวณเบี้ยประกัน — เอกสารออกแบบ (เฟส 1)

วันที่: 2026-09-03
สถานะ: รอผู้ใช้ตรวจทาน

## 1. เป้าหมาย

สร้างเว็บแอปคำนวณเบี้ยประกันภาษาไทย ที่ให้ผลลัพธ์ **ตรงกับโปรแกรมใบเสนอขาย Excel ของบริษัททุกสตางค์**
เพื่อให้ตัวแทนใหม่ (และในอนาคต ลูกค้า) กรอกอายุ เพศ แบบประกัน ทุน และสัญญาเพิ่มเติม แล้วได้เบี้ยทันที

เฟสนี้เป็นรากฐานของโปรเจกต์ใหญ่ (คลังความรู้ + AI ถามตอบ + LINE/Facebook + n8n)
เครื่องคำนวณที่สร้างในเฟสนี้จะถูก AI เรียกใช้ในเฟสถัดไปโดยตรง

## 2. ขอบเขต

### อยู่ในขอบเขต
- คำนวณ **เบี้ยประกัน** ของสัญญาหลักและสัญญาเพิ่มเติม ทั้งรายปีและตามงวดที่เลือก
- ตรวจ **กฎเงื่อนไข**: ช่วงอายุที่ซื้อได้ ทุนขั้นต่ำ/สูงสุด ข้อจำกัดระหว่างสัญญา เบี้ยรายเดือนขั้นต่ำ
- แบบประกันหลัก 5 แบบ จากไฟล์ Excel 5 ไฟล์ในโฟลเดอร์ `ไฟล์คำนวน/`
  1. Protection Life (PLB) — ทำก่อน
  2. iShield
  3. ไลฟ์เทรเชอร์
  4. ไอสมาร์ท 80-6
  5. Life Protect Plus 9/19/99
- สัญญาเพิ่มเติมทุกตัวที่ปรากฏในชีต `กรอกข้อมูล` ของแต่ละไฟล์
- งวดชำระ 3 แบบ: รายปี, ราย 6 เดือน, รายเดือน
- ปุ่มคัดลอกสรุปเป็นข้อความ
- แสดงเวอร์ชันตารางเบี้ยและวันหมดอายุ

### นอกขอบเขต (เฟสถัดไป)
- ขั้นอาชีพ (ระบบใช้ขั้น 1 เสมอ; ตารางอัตราขั้น 2–4 เก็บไว้ครบ แต่ไม่มี UI)
- งวดชำระราย 3 เดือน
- สรุปผลประโยชน์ / ตารางแสดงผลประโยชน์รายปี / มูลค่าเวนคืน (TABCV)
- พิมพ์ PDF, บันทึกใบเสนอ, ล็อกอิน, หน้า admin, API key, n8n, AI, LINE, Facebook

## 3. สถาปัตยกรรม

```
ไฟล์ Excel (ไฟล์คำนวน/*.xlsx)
        │  scripts/extract-rates.py  (Python + openpyxl)
        ▼
data/rates/<plan>.json  + data/rules/<plan>.json      ← ชั้นที่ 1: ข้อมูล
        │
        ▼
src/calc/**  (TypeScript ล้วน ไม่พึ่ง React)            ← ชั้นที่ 2: เครื่องคำนวณ
        │
        ▼
src/app/**  (Next.js App Router + Tailwind)             ← ชั้นที่ 3: หน้าเว็บ
```

- **เครื่องมือ:** Next.js (App Router) + TypeScript + Tailwind CSS, ฝากบน Vercel (แพ็กเกจฟรี)
- **ไม่มีฐานข้อมูล** ตารางอัตราเป็น JSON ในโปรเจกต์ (ข้อมูลเปลี่ยนปีละครั้ง)
- **ไม่มีล็อกอิน** เครื่องคำนวณไม่มีข้อมูลลับ
- **ไม่มี backend API** ในเฟสนี้ การคำนวณทำในเบราว์เซอร์ (เร็ว ไม่มีค่าใช้จ่าย) แต่โค้ดคำนวณแยกชั้นไว้ เฟส AI จะเรียกจากฝั่งเซิร์ฟเวอร์ได้ทันที
- ค่าใช้จ่าย: 0 บาท

## 4. ชั้นที่ 1: ข้อมูลอัตราและกฎ

### 4.1 หลักการ
ไม่พิมพ์ตัวเลขด้วยมือ ทุกตารางดึงจาก Excel ด้วยสคริปต์ เพื่อ (ก) ไม่พิมพ์ผิด (ข) อัปเดตเวอร์ชันใหม่ได้โดยรันสคริปต์ซ้ำ

### 4.2 สิ่งที่พบในไฟล์ Excel (ทุกไฟล์โครงสร้างเดียวกัน)
| ชีต | หน้าที่ |
|---|---|
| `กรอกข้อมูล` | อินพุต + กฎเงื่อนไข (ซ่อนในสูตร IF) + ผลลัพธ์ |
| `Cal` | คำนวณเบี้ย: ค้นอัตรา หักส่วนลด คูณทุน ปัดเศษ |
| `Premium&Maturity` | อัตราเบี้ยสัญญาหลักต่อทุน 1,000 แยก แบบ+เพศ (คอลัมน์) × อายุ (แถว) |
| `AP`, `ECARE`, `ELI`, `WP`, `Rate Rider`, ... | อัตราสัญญาเพิ่มเติม แยก อายุ × (เพศ / ขั้นอาชีพ / แบบหลัก) |
| `MEA+`, `MEB`, `Rate rider_MEX`, `iHealthy Ultra Rate` | เบี้ยคงที่ต่อปี แยก อายุ × เพศ × แผน |
| `WPD01`, `WPDD01` | อัตรายกเว้นเบี้ยกรณีผู้ชำระเบี้ย (สำหรับผู้เอาประกันเด็ก) |
| `Cal` แถว 27–32 | ตารางส่วนลดตามขนาดทุน แยกตามแบบ |
| `TABCV(*)`, `ตารางแสดงผลประโยชน์`, `ตารางมูลค่า` | มูลค่าเวนคืน/ผลประโยชน์รายปี — **นอกขอบเขตเฟสนี้** |

### 4.3 สูตรหลักที่ถอดได้ (จาก PLB, ใช้เป็นแม่แบบ)
```
rate      = lookup(Premium&Maturity, column = plan+sex, row = age)          # ต่อทุน 1,000
discount  = tier(plan, sumAssured)                                          # ต่อทุน 1,000
annual    = ROUNDDOWN((rate - discount) * sumAssured / 1000, 2)
modal     = ROUNDDOWN((rate - discount) * sumAssured / 1000 * modeFactor, 2)
modeFactor: รายปี 1, ราย 6 เดือน 0.52, รายเดือน 0.09
riderPrem = ROUNDDOWN(riderRate * riderSA / 1000, 2)                        # AP, ECARE, ELI, ...
fixedPrem = table(age, sex, plan)                                           # MEA+, MEB, MEX, iHealthy
riderModal= ROUNDDOWN(riderAnnual * modeFactor, 2)
```
ทุกจุดที่ Excel ใช้ `ROUNDDOWN(...,2)` / `TRUNC` / `ROUND` ต้องใช้ฟังก์ชันเดียวกันในโค้ด

### 4.4 รูปแบบไฟล์ข้อมูล
- `data/rates/<planCode>.json` — ตารางตัวเลขทั้งหมดของแบบนั้น พร้อม `version`, `effectiveFrom`, `expiresOn`, `sourceFile`, `extractedAt`
- `data/rules/<planCode>.json` — กฎเงื่อนไขที่ถอดจากสูตร IF ในชีต `กรอกข้อมูล` เขียนในรูปแบบอ่านง่าย เช่น
  ```json
  { "rider": "AP", "ageMin": 0, "ageMax": 60,
    "saMin": 100000, "saMax": { "multipleOfBase": 5, "cap": 10000000 } }
  ```
  ไฟล์กฎ **ผู้ใช้ต้องตรวจทาน** ว่าตรงกับที่สอนตัวแทน เพราะถอดจากสูตรด้วยมือ
- สคริปต์ `scripts/extract-rates.py` รันใหม่ได้เสมอ ผลลัพธ์ต้องเหมือนเดิม (deterministic)

## 5. ชั้นที่ 2: เครื่องคำนวณ (`src/calc`)

### 5.1 อินพุต
```ts
type QuoteInput = {
  planCode: string;            // "PLB12", "ISHIELD", ...
  age: number;                 // อายุผู้เอาประกัน
  sex: "M" | "F";
  mode: "annual" | "semi" | "monthly";
  sumAssured: number;          // ทุนสัญญาหลัก
  riders: Array<{ code: string; sumAssured?: number; plan?: string }>;
  payer?: { age: number; sex: "M" | "F" };   // จำเป็นเมื่อผู้เอาประกันอายุ < 16 และเลือก WPD/WPDD
};
```
ขั้นอาชีพไม่รับจากผู้ใช้ ใช้ค่า 1 เสมอ

### 5.2 เอาต์พุต
```ts
type QuoteResult = {
  items: Array<{ code: string; name: string; sumAssured: number;
                 annual: number; modal: number; eligible: boolean; message?: string }>;
  totalModal: number;
  totalAnnual: number;
  warnings: Array<{ level: "error" | "warn"; code: string; message: string }>;
  availability: Array<{ code: string; eligible: boolean; ageRange: string;
                        saMin?: number; saMax?: number; reason?: string }>;
  meta: { version: string; expiresOn: string; expired: boolean };
};
```
จำนวนเงินทั้งหมดคำนวณเป็น **สตางค์แบบจำนวนเต็ม** ภายใน แล้วแปลงเป็นบาทตอนส่งออก

### 5.3 โมดูล (แต่ละตัวทดสอบแยกได้)
| โมดูล | หน้าที่ | ขึ้นกับ |
|---|---|---|
| `rates/lookup.ts` | ค้นอัตราจาก JSON ตาม (ตาราง, แถว, คอลัมน์) คืน `undefined` ถ้าไม่พบ | JSON |
| `money.ts` | `roundDown2`, `round2`, แปลงบาท↔สตางค์ | — |
| `base-premium.ts` | เบี้ยสัญญาหลัก = อัตรา − ส่วนลด | lookup, money |
| `discount.ts` | ส่วนลดตามขนาดทุนและแบบ | JSON |
| `riders/<code>.ts` | หนึ่งไฟล์ต่อหนึ่งสัญญาเพิ่มเติม (AP, ECARE, ELI, MEA+, MEB, WP, WPD, WPDD, PLS, MEX, iHealthy Ultra, CI 123, ...) | lookup, money |
| `rules.ts` | ตรวจกฎจาก `data/rules` คืน availability + warnings | JSON |
| `quote.ts` | ตัวรวม: รับ `QuoteInput` คืน `QuoteResult` | ทุกตัวข้างบน |
| `plans/registry.ts` | รายชื่อแบบและสัญญาเพิ่มเติมที่แต่ละแบบรองรับ | JSON |

การเพิ่มแบบประกันใหม่ = เพิ่ม JSON + ลงทะเบียนใน registry + (ถ้ามี rider ใหม่) เพิ่มไฟล์ rider

## 6. ชั้นที่ 3: หน้าเว็บ (`src/app`)

หน้าเดียว แบ่งซ้าย/ขวา (มือถือ: เรียงบน/ล่าง) ภาษาไทยทั้งหมด

**ฝั่งซ้าย — ฟอร์ม**
1. เลือกแบบประกันหลัก
2. อายุ, เพศ, งวดชำระ (รายปี / ราย 6 เดือน / รายเดือน)
3. ทุนสัญญาหลัก แสดงขั้นต่ำ–สูงสุดใต้ช่อง
4. รายการสัญญาเพิ่มเติม: สวิตช์เปิด/ปิด + ช่องทุนหรือแผน; ตัวที่ซื้อไม่ได้เป็นสีเทาพร้อมช่วงอายุ
5. ช่องอายุ/เพศผู้ชำระเบี้ย ปรากฏเมื่ออายุ < 16

**ฝั่งขวา — ผลลัพธ์** (อัปเดตทันที ไม่มีปุ่มคำนวณ)
- ตารางเบี้ยรายรายการ + ยอดรวมต่องวด (ตัวใหญ่)
- กล่องคำเตือน (เหลือง = warn, แดง = error)
- ปุ่ม "คัดลอกสรุป" → ข้อความสั้นสำหรับส่ง LINE
- เวอร์ชันตารางเบี้ย + วันหมดอายุ มุมล่าง; แถบเตือนด้านบนถ้าหมดอายุ

## 8. การทดสอบ

### 8.1 Golden tests เทียบกับ Excel (สำคัญที่สุด)
1. `scripts/make-golden.py` เขียนชุดอินพุตลงชีต `กรอกข้อมูล` ของสำเนาไฟล์ Excel
2. ให้ **LibreOffice headless** (`/opt/homebrew/bin/soffice` มีบนเครื่องแล้ว) คำนวณใหม่แล้วแปลงกลับ
3. อ่านเบี้ยแต่ละรายการและยอดรวมออกมาเป็น `tests/golden/<plan>.json`
4. ชุดทดสอบ (Vitest) รันเครื่องคำนวณด้วยอินพุตเดียวกัน ต้องตรง **ทุกสตางค์**
5. อย่างน้อย **50 กรณี/แบบ** ครอบคลุม: อายุขอบล่าง/บน, ทุนตรงจุดเปลี่ยนส่วนลด, ทุกงวดชำระ, ทุก rider, กรณีที่ต้องขึ้นคำเตือน, ผู้เอาประกันเด็ก + ผู้ชำระเบี้ย

**ความเสี่ยง:** LibreOffice อาจคำนวณต่างจาก Excel ในบางฟังก์ชัน หากพบค่าที่น่าสงสัย จะขอให้ผู้ใช้ตรวจกรณีนั้นใน Excel จริง และบันทึกไว้ในไฟล์ golden ว่ามาจาก Excel

### 8.2 Unit tests
- `money.ts`: ปัดเศษทุกแบบ รวม edge case ทศนิยม
- `discount.ts`: ทุกจุดเปลี่ยนขั้น (349,999 / 350,000 / 499,999 / 500,000 ...)
- `rules.ts`: ทุกกฎ ทั้งผ่านและไม่ผ่าน
- แต่ละ rider: ค้นอัตราถูกช่อง

### 8.3 ทดสอบหน้าเว็บ
- ตรวจด้วยมือบนมือถือและคอม ตามรายการตรวจในแผนงาน
- ไม่มี E2E อัตโนมัติในเฟสนี้
