# การ์ดราคาสำหรับชุดประกันของเอเจนซี่

วันที่ 2026-09-11

## ปัญหา

ลูกค้าที่ถามราคาแบบประกันเดี่ยวในแชทได้รูปการ์ดกลับไปด้วย — สรุปเบี้ย ผลประโยชน์
มูลค่าเงินสด บนพื้นหลังของเอเจนซี่ เซฟเก็บได้ ส่งต่อให้คนที่บ้านดูได้

ลูกค้าที่ถามชุด "มรดกเพื่อครอบครัว" ได้แต่ตัวอักษร

`answerBundle()` ใน `src/lib/assistant/answer.ts` คืนแค่ `reply` กับ `sources`
ไม่มี `card` ผลคือทั้งสามช่องทางเงียบเหมือนกันหมด เพราะทุกช่องทางส่งรูปเมื่อมี
`answer.card` เท่านั้น — เว็บแชทที่ `ChatClient.tsx`, LINE ที่ `line/webhook/route.ts`,
Messenger ที่ `facebook/webhook/route.ts`

ชุดมรดกเป็นสินค้าที่เอเจนซี่ขายภายใต้ชื่อตัวเอง และเป็นตัวที่ยิงโฆษณาอยู่
ช่องทางที่ปิดการขายกลับเป็นช่องทางเดียวที่ไม่มีรูปให้ลูกค้าถือกลับไป

สี ฟอนต์ ความกว้าง ระยะห่าง เป็นของเดิมทั้งหมด ลูกค้าต้องอ่านออกว่าเป็นการ์ด
ชุดเดียวกับที่เคยเห็น

## เรื่องที่ตัดสินใจไว้แล้ว

### เบี้ยปีแรก

เบี้ย DCI คิดจากอายุที่บรรลุ จึงขึ้นทุกปี ทุกตัวเลขที่ลูกค้าเห็นเป็นเบี้ยปีแรก

หน้าขาย `/legacy` บอกเรื่องนี้ไว้แล้วที่ `LegacyCalculator.tsx` แต่ข้อความที่แชท
ตอบชุดมรดกไม่ได้บอก เขียนแค่ "เบี้ยประมาณการจากตารางเบี้ยบริษัท" ที่
`format.ts` บรรทัด 143

รูปอยู่ได้นานกว่าข้อความ ลูกค้าเซฟไว้ ส่งต่อในไลน์กลุ่ม แล้วเอากลับมาอ้างอีกสามปี
การ์ดที่ไม่บอกว่าเป็นเบี้ยปีแรกคือการ์ดที่สร้างข้อโต้แย้งให้ตัวแทนในภายหลัง

**พาดหัวเขียนแค่ "บาท ต่อปี"** ไม่ใส่วงเล็บ "(ปีแรก)" — คำเตือนอยู่ในหมายเหตุ
ท้ายการ์ดสองบรรทัด

ข้อความที่แชทตอบก็จะได้หมายเหตุเดียวกันนี้ด้วย ปัญหาเดียวกันไม่ควรแก้แค่ที่รูป

### ช่องบนการ์ด

การ์ดของชุดมีทุกช่องที่การ์ดเดี่ยวมี บวกสองช่องที่มีแต่ชุดเท่านั้นที่มี —
รายการสัญญาที่ประกอบกัน และเงินก้อนกรณีโรคร้ายแรง

ช่องมูลค่าเงินสดคิดจากสัญญาหลัก 150,000 บาท ตัวเลขจึงเป็นหลักหมื่น อยู่ใต้หัวข้อ
"มรดก 1 ล้าน" แล้วดูขัดกัน เรื่องนี้แจ้งผู้ใช้แล้วและผู้ใช้เลือกให้คงไว้ เพราะเป็น
เงินที่มีอยู่จริงและลูกค้าถามถึง

### ช่วงอายุบนช่องเสียชีวิต

ไม่เขียนเอง ใช้ `deathBenefitRows()` ที่ `src/lib/death-benefit.ts` ตัวเดียวกับที่
หน้าขายและใบสรุปใช้

ฟังก์ชันนี้ปิดช่วงอายุท้ายทั้งสองด้านเมื่อมีอะไรตามมา — เขียน "อายุ 60–74 ปี"
ไม่ใช่ "อายุ 60 ปีขึ้นไป" เพราะ DCI จบที่ 75 การ์ดที่เขียนแบบหลังคือการ์ดที่
สัญญาความคุ้มครองที่หมดไปแล้ว

ผลพลอยได้: ก่อนอายุ 60 ตัวเลขเป็น 1,150,000 ไม่ใช่ 1,000,000 เพราะ Life Protect
**x 2** คูณสองทุนหลัก 150,000 ก่อนอายุ 60 เครื่องคำนวณรู้เรื่องนี้อยู่แล้ว

## โครงสร้าง

### หนึ่ง — `QuoteCard` เปลี่ยนจากช่องตายตัวเป็นลิสต์ของช่อง

วันนี้ `QuoteCard` มีฟิลด์ `death` กับ `cash` และ `route.tsx` วาดสองช่องนั้นแบบ
เขียนตายตัว ชุดมรดกต้องการสี่ช่อง

เปลี่ยนเป็น `sections: CardSection[]` แล้วให้เครื่องวาดวนลูป

```ts
export interface CardSection {
  title: string;
  rows: CardRow[];
}
```

`heightOf()` รวมความสูงจากลิสต์แทนที่จะบวกสองช่องด้วยมือ

ทำแบบนี้เพราะแผนที่เหลืออีกสี่แผนจะมาต่อคิวทีหลัง ถ้าเติมฟิลด์ทีละช่องตอนนี้
ก็ต้องกลับมาแก้เครื่องวาดซ้ำอีกสี่รอบ

ช่องอื่น — `planLine`, `insuredLine`, `premium`, `perDay`, `others`, `notes` —
ไม่แตะ

### สอง — `CardInput` รับได้สองแบบ

```ts
export type CardInput = PlanCardInput | BundleCardInput;

export interface BundleCardInput {
  kind: "bundle";
  bundleCode: string;
  tier: number;
  age: number;
  sex: Sex;
  mode?: PayMode;
}
```

`PlanCardInput` คือของเดิม เติม `kind: "plan"` เพื่อแยกออกจากกัน

ลิงก์: `/api/card?bundle=LEGACY_FAMILY&tier=1&age=40&sex=M&mode=annual`

`cardInputFrom()` อ่าน `bundle` ก่อน ถ้ามีก็ตรวจกับทะเบียนชุดและตรวจว่า `tier`
มีอยู่จริง ถ้าไม่มีก็ตกไปทางเดิม

### สาม — `bundleCard()` สร้าง `QuoteCard` ตัวเดียวกัน

อยู่ใน `src/lib/quote-card.ts` ข้าง `quoteCard()` คืนโครงเดียวกัน เครื่องวาดจึง
ไม่ต้องรู้ว่ากำลังวาดแผนเดี่ยวหรือชุด

ใช้ของที่มีอยู่แล้วทั้งหมด — `quoteBundle()`, `bundleModePremiums()`,
`describeTier()`, `deathBenefitRows()`, `cashValueSchedule()`, `displayPremium()`

`quoteCard()` เปลี่ยนเป็นตัวแยกทาง: `kind === "bundle"` ไป `bundleCard()`
นอกนั้นไปทางเดิม

### สี่ — `answerBundle()` แนบการ์ด

แนบเฉพาะตอนที่คำนวณราคาได้จริง ซึ่งคือจุดเดียวกับที่ `priced: true` อยู่แล้ว
ที่ `answer.ts` บรรทัด 178

สามช่องทางไม่ต้องแก้อะไรเลย ทุกช่องทางส่งรูปเมื่อมี `answer.card` อยู่แล้ว

## การ์ดจะไม่ออกเมื่อไหร่

รูปที่ผิดแย่กว่าไม่มีรูป กติกาเดียวกับการ์ดเดิม — ไม่มีราคาที่ขายได้จริง
ก็ไม่มีรูป ข้อความที่แชทตอบยังอธิบายเหตุผลเหมือนเดิม

| สถานการณ์ | ผล |
|---|---|
| อายุนอกช่วง 20–65 ปี | ไม่มีการ์ด |
| จัดชุดไม่ครบ (`BUNDLE_INCOMPLETE`) | ไม่มีการ์ด |
| warning ระดับ error อื่น | ไม่มีการ์ด |
| ยังไม่รู้เพศ อายุ หรือวงเงิน | ไม่มีการ์ด — แชทกำลังถามข้อมูลอยู่ |
| `tier` ไม่มีในชุด | HTTP 400 |
| `bundle` ไม่มีในทะเบียน | HTTP 400 |
| ตารางเบี้ยหมดอายุ | มีการ์ด ไม่มีราคา เขียน "ขอราคาปัจจุบันได้ทางแชท" |

ยกเว้นข้อเดียวคือ `MIN_MONTHLY` ซึ่งเป็นเรื่องของงวดผ่อน ไม่ใช่เรื่องของชุด

ชาย 40 มรดก 1 ล้าน เบี้ยรายเดือน 698 บาท ต่ำกว่าขั้นต่ำ 1,000 บาท การ์ดจึงไม่
โชว์งวดรายเดือนในบรรทัดงวดอื่น และพาดหัวใช้รายปีแทน `displayPremium()` ที่
`src/lib/legacy-cta.ts` ทำเรื่องนี้อยู่แล้ว

## ความปลอดภัยของลิงก์

ลิงก์บอกว่าจะวาด "อะไร" ไม่เคยบอกว่าราคา "เท่าไหร่" ราคาคำนวณใหม่จากตารางเบี้ย
ทุกครั้งที่วาด ลิงก์ที่ถูกแก้ด้วยมือจึงทำให้บริษัทโฆษณาเบี้ยที่ไม่เคยเสนอไม่ได้

หลักการนี้เป็นของเดิม เขียนไว้ใน `quote-card.ts` แล้ว ชุดใช้หลักการเดียวกัน

## การทดสอบ

เขียนเทสต์ก่อนโค้ด ต่อจาก `tests/calc/quote-card.test.ts`

- ตัวเลขบนการ์ดตรงกับ `tests/golden/legacy-family.test.ts` — ตารางเบี้ยเปลี่ยน
  แล้วการ์ดเพี้ยน เทสต์ต้องฟ้อง
- อายุ 19 และ 66 ไม่ได้การ์ด
- `tier` นอกช่วง 1–10 ไม่ได้การ์ด
- `bundle` ที่ไม่มีในทะเบียนไม่ได้การ์ด
- หมายเหตุ "เบี้ยปีแรก" อยู่บนการ์ดทุกใบ
- ช่องเสียชีวิตมีสามบรรทัดสำหรับอายุ 40 และตัวเลขก่อน 60 คือ 1,150,000
- `MIN_MONTHLY` ไม่ทำให้การ์ดหาย และพาดหัวเป็นรายปี
- การ์ดแบบเดี่ยวเดิมออกมาเหมือนเดิมทุกจุด — กันการรื้อ `sections` ไปทำของเก่าพัง
- `answerBundle()` แนบ `card` เมื่อคำนวณได้ และไม่แนบเมื่อยังถามข้อมูลอยู่

จบด้วยการยิงการ์ดจริงออกมาเป็นรูป ให้ผู้ใช้ดูก่อนตัดสินใจว่าจะขึ้นจริงไหม

## ไม่ทำในรอบนี้

- ไม่ทำการ์ดให้อีกสี่แผนที่เหลือ รอบนี้วางโครงให้ต่อได้ แต่ยังไม่ต่อ
- ไม่แตะรูปโฆษณาสี่ใบใน `public/ads/lifeprotect-x2/`
- ไม่เปลี่ยนสี ฟอนต์ หรือขนาดการ์ด
- ไม่เพิ่มตารางเบี้ยตามอายุลงการ์ด — ผู้ใช้เลือกไม่เอา
