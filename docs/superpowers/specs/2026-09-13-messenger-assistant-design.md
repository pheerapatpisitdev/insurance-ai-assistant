# ผู้ช่วยตอบลูกค้าบน Facebook Messenger — Life Protect x 2

วันที่ 2026-09-13

## ปัญหา

เอเจนซี่ยิงโฆษณา Life Protect x 2 อยู่ และคนที่เห็นโฆษณาทักเข้ามาที่เพจโดยตรง
ปลายทางของเงินค่าโฆษณาทุกบาทคือกล่องข้อความของเพจ ซึ่งตอนนี้ไม่มีใครอยู่

บอทที่เคยตอบตรงนั้นถูกถอดออกเมื่อ 11 ก.ย. 2569 (`7fb20b8` ถอด Messenger, `cfa8dbc`
ถอดผู้ช่วยทั้งตัว) สิ่งที่เหลืออยู่คือ

- ชั้นเรียกโมเดลใน `src/lib/ai/` — สลับผู้ให้บริการอัตโนมัติ เพดานงบรายเดือน บัญชีค่าใช้จ่าย
- ตารางเดิมใน Supabase ครบทุกใบ (`ins_chat_sessions`, `ins_chat_events`, `ins_channel_auth`,
  `ins_usage_ledger`, `ins_faq`) แต่ `ins_channel_auth` **ว่างเปล่า** — โทเคนเพจหายไปแล้ว
- เครื่องคำนวณและหน้าขาย `/lifeprotect` พร้อมกับ `lifeProtectQuoteText()` ที่เขียนใบเสนอราคา
  เป็นข้อความแชทได้อยู่แล้ว และ `/api/card` ที่วาดใบเสนอราคาเป็นรูป

โค้ดที่ถอดออกยังอยู่ในประวัติ git ทั้งหมด รอบนี้จึงเป็นการ **กู้ของเก่าแล้วหั่นให้เหลือเท่าที่ใช้**
ไม่ใช่การเขียนใหม่

## สิ่งที่จะสร้าง

บอทที่ตอบในกล่องข้อความของเพจ LuckyPlanner เรื่องแบบประกัน Life Protect x 2 แบบเดียว

```
ลูกค้า: สนใจครับ
บอท:   สวัสดีครับ 🙏 Life Protect+ 100 คุ้มครองถึงอายุ 99 ปี
       เสียชีวิตก่อนอายุ 60 ครอบครัวรับ 2 เท่าของทุน
       รบกวนบอก อายุ / เพศ / ทุนที่สนใจ ครับ (เช่น "ชาย 35 ทุน 1 ล้าน")

ลูกค้า: ชาย 35 ล้านนึง
บอท:   [ใบเสนอราคาเต็มจาก lifeProtectQuoteText()]
       [การ์ดรูปจาก /api/card]
       สนใจจ่ายให้จบเร็วกว่านี้ไหมครับ มีแบบจ่าย 9 ปี และ 19 ปี

ลูกค้า: 19 ปีเท่าไหร่
บอท:   [ใบเสนอราคาของแบบ 19 ปี + การ์ดใหม่]

ลูกค้า: ป่วยหนักได้เงินไหม
บอท:   [ตอบจากข้อมูลหน้าขาย หรือบอกว่าขอให้ตัวแทนตอบ]
```

กติกาที่บอทห้ามข้าม

- ตัวเลขทุกตัวมาจากเครื่องคำนวณ ไม่ใช่จากโมเดล
- ไม่ถามเลขบัตรประชาชน ประวัติสุขภาพ เลขกรมธรรม์ หรือข้อมูลการชำระเงิน
- ไม่รับสมัคร ไม่รับประกันผลการพิจารณา
- ใบเสนอราคาทุกใบปิดท้ายว่าเป็นเบี้ยมาตรฐานโดยประมาณ ไม่ใช่ใบเสนอราคาจริง
- ถามเรื่องนอกขอบเขต (แบบประกันอื่น การเคลม เงื่อนไขสุขภาพ) → บอกตรงๆ แล้วส่งไม้ให้ตัวแทน

## สถาปัตยกรรม

### เส้นทางของข้อความ

```
ลูกค้าพิมพ์ → Meta → POST /api/facebook/webhook
  1. ตรวจลายเซ็น x-hub-signature-256 ด้วย FB_APP_SECRET       ← ไม่ผ่าน = 401
  2. ตอบ 200 ทันที แล้วทำงานต่อใน after()                      ← Meta รอได้ไม่กี่วินาที
  3. claimEvent() กันข้อความซ้ำจากการส่งซ้ำของ Meta
  4. hashUserId() แปลง PSID เป็นแฮช HMAC
  5. เซสชันถูกปิดปากอยู่ไหม (muted_until) → เงียบ
  6. loadSession() ดึง 6 เทิร์นล่าสุดของ 24 ชม.
  7. routeMessage() โมเดลเล็กอ่านเป็น JSON
  8. answerQuestion() เลือกเส้นทาง
  9. sendMessage() แล้ว sendImage() ถ้ามีการ์ด
 10. saveSession()
```

### สมองของบอท

`answerQuestion()` แยกสี่ทาง ตาม `intent` ที่โมเดลเล็กอ่านได้

| เส้นทาง | ที่มาของคำตอบ | โมเดลมีส่วนไหม |
| --- | --- | --- |
| `quote` | `quote()` + `lifeProtectQuoteText()` + `cardPath()` | ไม่ ทั้งตัวเลขและถ้อยคำ |
| `plan_info` | ข้อเท็จจริงจาก `lifeProtectFacts()` และ `lifeProtectTable()` | เรียบเรียงเท่านั้น ห้ามเติมตัวเลขเอง |
| `other` (ทักทาย) | คำทักสั้นๆ ที่เขียนไว้ + วกเข้าคำถาม อายุ/เพศ/ทุน | ไม่ |
| นอกขอบเขต | ประโยคที่เขียนไว้ + ส่งไม้ให้ตัวแทน | ไม่ |

`Routed` หั่นจากของเดิมให้เหลือ `{ intent, age, sex, sumAssured, variant, mode, question }`
— ทิ้ง `planCode`, `bundleCode`, `tier` เพราะรอบนี้มีแบบประกันเดียวและไม่มีชุดจัดเอง
และ `Intent` เหลือสามค่า `"quote" | "plan_info" | "other"` — ทิ้ง `"doc_qa"` ไปพร้อมกับคลังความรู้
คำถามที่เคยตกเส้นทางนั้น (การเคลม ระยะรอคอย ข้อยกเว้น) กลายเป็นเรื่องนอกขอบเขตที่ส่งไม้ให้ตัวแทน

รหัสของแบบการชำระคือ `WLF09H` `WLF19H` `WLF99H` — ตัวท้าย `H` คือ x 2 ส่วน `L` คือ x 1.5
ซึ่งไม่ใช่ตัวที่ยิงโฆษณาอยู่ บอทจึงเสนอเฉพาะสามรหัสที่ลงท้ายด้วย `H`

**แบบการชำระ** Life Protect x 2 มีสามแบบ (`WLF09H` จ่าย 9 ปี, `WLF19H` จ่าย 19 ปี,
`WLF99H` ครบอายุ 99) ถ้าลูกค้าไม่ระบุ บอทเสนอ **ครบอายุ 99** ซึ่งเบี้ยต่ำสุด แล้วต่อท้ายว่า
มีอีกสองแบบให้เลือก ถ้าลูกค้าเอ่ยถึงแบบใดในข้อความต่อมา เสนอใบใหม่ของแบบนั้น

**เมื่อคำนวณไม่ได้** อายุเกินช่วงที่รับ หรือทุนต่ำกว่าขั้นต่ำ — เครื่องคำนวณคืนคำเตือนระดับ
`error` อยู่แล้ว บอทบอกเหตุผลเป็นคำพูด (เช่น "แบบนี้รับถึงอายุ 70 ครับ") แล้วชวนคุยกับตัวแทน
ไม่ส่งการ์ด

**เมื่อตารางเบี้ยหมดอายุ** `result.meta.expired` เป็นจริง — ไม่แสดงราคาใดๆ บอกว่าขอราคา
ปัจจุบันจากตัวแทน เส้นทางนี้มีอยู่แล้วทั้งใน `premiumLines()` และ `displayPremium()`

## เงียบเมื่อตัวแทนเข้ามาตอบ

Meta ส่งสำเนา (`is_echo`) ของทุกข้อความที่ออกจากเพจ พร้อม `app_id` ของแอปที่ส่ง

- `app_id` ตรงกับ `FB_APP_ID` = บอทส่งเอง ไม่ต้องทำอะไร
- ไม่มี `app_id` หรือไม่ตรง = คนพิมพ์จากกล่องข้อความของเพจ → ตั้ง
  `muted_until = now() + 24 ชั่วโมง` ของเซสชันนั้น
- ข้อความของลูกค้าที่เข้ามาระหว่างถูกปิดปาก บอทไม่ตอบและไม่เสียค่าโมเดล
  (ตรวจก่อนเรียก `routeMessage()`)
- ครบเวลา บอทกลับมาตอบเอง

เพิ่มคอลัมน์เดียวใน `ins_chat_sessions`

```sql
alter table ins_chat_sessions add column if not exists muted_until timestamptz;
```

`muted_until` ถูกอ่านแม้เซสชันจะเก่ากว่า 24 ชม. แล้ว เพราะการปิดปากมีอายุของตัวเอง

## ความเป็นส่วนตัว

หน้า `/privacy` ตอนนี้เขียนว่าไม่เก็บข้อมูลอะไรของผู้เข้าชมเลย ซึ่งจะไม่จริงอีกต่อไป
ต้องเขียนใหม่ให้ตรงกับสิ่งที่ระบบทำจริง และ Meta ก็ตรวจข้อนี้ตอนเชื่อมแอป

- เก็บข้อความในบทสนทนาไว้ไม่เกิน 24 ชั่วโมง เพื่อให้ถามต่อเนื่องได้ แล้วลบ
- เก็บตัวตนของผู้ส่งเป็นค่าแฮช HMAC เท่านั้น ย้อนกลับเป็น PSID ไม่ได้
- บัญชีค่าใช้จ่ายเก็บแต่จำนวนโทเคนและเงิน ไม่เก็บคำพูดของลูกค้า
- วิธีขอลบข้อมูลอยู่ที่ `/privacy#rights`

## การทดสอบ

เทสต์อัตโนมัติ (vitest)

- `routeMessage()` อ่านข้อความไทยจริงเป็นข้อมูลถูกต้อง — ทดสอบกับคำตอบโมเดลที่ถูกแทนไว้
  ("ชาย 35 ล้านนึง", "อายุ 42 หญิง ทุน 5 แสน จ่าย 19 ปี", "แรกเกิด")
- `answerQuestion()` เลือกเส้นทางถูก และเส้นทาง `quote` คืนข้อความกับการ์ดที่ตรงกับ
  `lifeProtectQuoteText()` ตัวเดียวกับที่หน้าขายใช้
- อายุนอกช่วง ทุนต่ำกว่าขั้นต่ำ และตารางหมดอายุ — ไม่มีราคาหลุดออกไป และไม่มีการ์ด
- `toParts()` ตัดข้อความยาวเกิน 1,900 ตัวอักษร
- `verifySignature()` ปฏิเสธลายเซ็นปลอมและคำขอที่ไม่มีลายเซ็น
- ตรรกะปิดปาก: echo ของคนตั้งเวลา echo ของบอทไม่ตั้ง ระหว่างปิดปากไม่เรียกโมเดล

ทดสอบด้วยมือก่อนถือว่าเสร็จ

- ทักเพจจากบัญชี Facebook ที่ไม่มีบทบาทใดในแอป แล้วได้ใบเสนอราคาและการ์ดกลับมา
- พิมพ์ตอบจากกล่องข้อความของเพจ แล้วลูกค้าทักต่อ — บอทต้องเงียบ
- `npm run verify` ผ่านทั้งชุด
