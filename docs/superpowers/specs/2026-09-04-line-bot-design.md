# LINE บอทถามตอบและคิดเบี้ย — เอกสารออกแบบ

วันที่: 2026-09-04
สถานะ: อนุมัติแล้ว (ผู้ใช้ยืนยันครบ 3 ส่วน)

## 1. เป้าหมาย

ให้ตัวแทนและลูกค้าทักเข้ามาในบัญชี LINE ทางการของผู้ใช้ พิมพ์เป็นภาษาไทยธรรมดา
แล้วได้คำตอบ 3 แบบ: คิดเบี้ยประกัน, ตอบเรื่องแบบประกันจากกฎในระบบ, ตอบจากเอกสาร PDF
ในคลังความรู้ โดย **ตัวเลขเบี้ยทั้งหมดมาจากเครื่องคำนวณเดียวกับเว็บ ไม่ใช่จาก AI**

## 2. ขอบเขต

### อยู่ในขอบเขต
- Webhook รับข้อความจาก LINE Messaging API พร้อมตรวจลายเซ็น
- แยกเจตนาและดึงค่าจากข้อความด้วยโมเดลเล็ก (intent + slots)
- เจตนา `quote` → เรียก `quote()` ตัวเดิม → ตอบข้อความสรุป
- เจตนา `plan_info` → ตอบจาก `data/rules/*.json` + `data/rates/*.json`
- เจตนา `doc_qa` → ค้นคลังความรู้ (เวกเตอร์ + คำตรง) → โมเดลใหญ่สรุปพร้อมอ้างอิงไฟล์และหน้า
- ท่อเอกสาร: ดึงข้อความจาก PDF → ตัดท่อน → ฝังเวกเตอร์ ตอนอัปโหลดในหน้าหลังบ้าน
- บันทึกค่าใช้จ่าย AI ลง `public.usage_ledger` และหยุดเรียก AI เมื่อถึงงบต่อเดือน
- จำบทสนทนา 6 ข้อความล่าสุดต่อคน ลบอัตโนมัติหลัง 24 ชั่วโมง

### นอกขอบเขต (เฟสถัดไป)
- แยกสิทธิ์ตัวแทนกับลูกค้า (เก็บธงไว้ แต่ตอบเหมือนกันทุกอย่าง ตามที่ผู้ใช้เลือก)
- Facebook Messenger, n8n
- ส่งข้อความหาลูกค้าเอง (push) — รอบนี้ตอบเมื่อถูกทักเท่านั้น

## 3. สถาปัตยกรรม

```
LINE ──POST──► /api/line/webhook ──(ตรวจ x-line-signature)──► ตอบ 200 ทันที
                                                                 │
                                            ประมวลผลเบื้องหลัง ◄─┘
                                                 │
                    โมเดลเล็ก: intent + slots ───┤
                                                 ├─ quote      → src/calc/quote.ts
                                                 ├─ plan_info  → data/rules + data/rates
                                                 └─ doc_qa     → ค้น ins_doc_chunks → โมเดลใหญ่
                                                 │
                                        LINE reply API
```

- ทุกอย่างอยู่ใน Next.js เดิม ไม่มีบริการใหม่
- เข้าฐานข้อมูลด้วย service-role key ฝั่งเซิร์ฟเวอร์เท่านั้น (เหมือนหลังบ้าน)

## 4. ตารางใหม่ (`public.ins_*`, RLS เปิด ไม่มี policy)

| ตาราง | หน้าที่ | คอลัมน์หลัก |
|---|---|---|
| `ins_doc_chunks` | ท่อนข้อความจาก PDF พร้อมเวกเตอร์ | `id`, `doc_id` → `ins_knowledge_docs`, `page`, `content`, `embedding vector(1536)`, `created_at` |
| `ins_line_sessions` | บทสนทนาล่าสุดต่อผู้ใช้ | `user_hash` (pk), `messages jsonb`, `is_agent boolean`, `updated_at` |
| `ins_line_events` | กันประมวลผลซ้ำเมื่อ LINE ส่งซ้ำ | `event_id` (pk), `created_at` |

- `user_hash` = HMAC-SHA256 ของ LINE userId ด้วย `ADMIN_SESSION_SECRET` — ย้อนกลับไม่ได้
- `ins_line_sessions` เก็บ 6 ข้อความล่าสุด ลบทิ้งเมื่อเก่ากว่า 24 ชั่วโมง
- ต้องเปิดส่วนขยาย `vector` (0.8.2) และ `pgroonga` (3.2.5) ทั้งคู่พร้อมใช้ในโปรเจกต์นี้

## 5. การแยกเจตนา

โมเดลเล็กได้รับข้อความล่าสุด + บทสนทนาย้อนหลัง แล้วคืน JSON ที่บังคับรูปแบบ:

```json
{
  "intent": "quote | plan_info | doc_qa | other",
  "planCode": "LIFEPROTECT | ISMART | LIFETREASURE | ISHIELD | PLB | null",
  "variant": "รหัสแพ็กเกจ หรือ null",
  "age": 35, "sex": "M", "mode": "annual",
  "sumAssured": 1000000, "riders": [{"code": "AP", "sumAssured": 500000}],
  "missing": ["age"],
  "question": "ข้อความคำถามเมื่อ intent ไม่ใช่ quote"
}
```

- ค่าที่ขาดไปอยู่ใน `missing` → บอทถามกลับทีละอย่าง ไม่เดา
- ชื่อแบบประกันภาษาไทยและอังกฤษถูกจับคู่ด้วยตารางชื่อพ้อง เช่น "ไลฟ์โพรเทค 100", "LP100"
- ถ้าโมเดลคืน JSON ผิดรูป ระบบลองใหม่ 1 ครั้ง แล้วตอบว่าไม่เข้าใจ

## 6. การตอบแต่ละแบบ

**quote** เรียก `quote()` ตรง ๆ แล้วส่งข้อความรูปแบบเดียวกับปุ่ม "คัดลอกสรุปส่ง LINE" บนเว็บ
พร้อมลิงก์เว็บที่เติมค่าไว้ให้แล้ว เพื่อกดดูรายละเอียดต่อได้

**plan_info** ประกอบคำตอบจากไฟล์กฎ (ช่วงอายุ ทุนขั้นต่ำสูงสุด รายชื่อสัญญาเพิ่มเติม)
ส่งให้โมเดลเล็กเรียบเรียงเป็นภาษาคน โดยห้ามเพิ่มข้อมูลนอกเหนือจากที่ให้

**doc_qa** ค้น 2 ทางแล้วรวมผล
1. เวกเตอร์: `embedding <=> query_embedding` เอา 8 อันดับแรก
2. คำตรง: pgroonga บนคอลัมน์ `content` เอา 8 อันดับแรก
3. รวม จัดอันดับใหม่ เลือก 5 ท่อน ส่งให้โมเดลใหญ่พร้อมคำสั่งให้ตอบเฉพาะจากท่อนที่ให้
   และอ้างอิงชื่อไฟล์กับเลขหน้า ถ้าไม่พบให้ตอบว่าไม่พบในเอกสาร

## 7. ค่าใช้จ่ายและการคุมงบ

- อ่านโมเดลเริ่มต้นและงบจาก `public.app_settings`
- ทุกการเรียก AI บันทึก `usage_ledger` (model, task, units, cost_thb) — ไม่เก็บข้อความลูกค้า
- ก่อนเรียกทุกครั้ง รวมยอดเดือนนี้ ถ้าถึงงบ ตอบข้อความขออภัยแทนการเรียก AI
- ประมาณการ: แยกข้อความ ~0.0002 บาท/ครั้ง, ตอบเอกสาร ~0.003 บาท/ครั้ง, ฝังเวกเตอร์ ~1 บาท/PDF 100 หน้า

## 8. ความปลอดภัยและความเป็นส่วนตัว

- ตรวจ `x-line-signature` ด้วย channel secret แบบ timing-safe ทุกคำขอ ไม่ผ่าน = 401
- ตอบ 200 ให้ LINE ภายใน 1 วินาที แล้วทำงานต่อเบื้องหลัง
- กันซ้ำด้วย `ins_line_events` (LINE ส่งซ้ำได้เมื่อ timeout)
- จำกัด 10 ข้อความต่อคนต่อนาที เกินแล้วเงียบ
- ไม่เก็บชื่อ รูปโปรไฟล์ หรือเบอร์โทร รหัสผู้ใช้เก็บแบบแฮชทางเดียว
- ข้อความจากผู้ใช้ถือเป็นข้อมูล ไม่ใช่คำสั่ง ระบบไม่ทำตามคำสั่งที่ฝังมาในข้อความ

## 9. ตัวแปรใหม่ที่ต้องตั้ง

```
LINE_CHANNEL_SECRET=        # LINE Developers → Messaging API channel → Basic settings
LINE_CHANNEL_ACCESS_TOKEN=  # ปุ่ม Issue ที่หน้า Messaging API
```

ตั้งใน `.env.local` และใน Vercel ทั้ง production/preview/development

## 10. การทดสอบ

- ตรวจลายเซ็น: คำขอปลอมถูกปฏิเสธ, คำขอจริงผ่าน
- แยกเจตนา: ชุดข้อความไทยจริง 30 ประโยค เทียบกับ intent และ slots ที่ควรได้
- คิดเบี้ยผ่านบอท: ผลต้องเท่ากับ `quote()` ทุกกรณี (ใช้ชุดเดียวกับ golden)
- ค้นเอกสาร: อัปโหลด PDF ตัวอย่าง แล้วถามคำถามที่คำตอบอยู่ในไฟล์
- งบ: ตั้งงบต่ำแล้วยืนยันว่าบอทหยุดเรียก AI
- ชุดเทสเดิม 445 ข้อต้องยังผ่านทั้งหมด

## 11. สิ่งที่ผู้ใช้ต้องทำ

1. เข้า https://developers.line.biz → สร้าง Provider → สร้าง Messaging API channel ผูกกับ LINE OA ที่มีอยู่
2. คัดลอก **Channel secret** และกด Issue เพื่อรับ **Channel access token**
3. ส่งค่าทั้งสองให้ระบบ (ผมจะบอกวิธีใส่โดยไม่ต้องพิมพ์ในแชท)
4. ปิด Auto-reply และ Greeting message ในหน้า LINE Official Account Manager ไม่งั้นบอทจะตอบซ้อนกับข้อความอัตโนมัติ
5. อัปโหลด PDF อย่างน้อย 1 ไฟล์ในหน้าหลังบ้าน เพื่อทดสอบการตอบจากเอกสาร
