# กราฟและตารางมูลค่ากรมธรรม์ บนหน้าขาย Life Protect+ 100

วันที่ 2026-09-12

## ปัญหา

หน้า `/lifeprotect` บอกมูลค่าเงินสดไว้สี่บรรทัด — อายุ 60, 70, 80 และ 99

```
มูลค่าเงินสดสะสม (หากเวนคืน)
  อายุ 60 ปี        243,000 บาท
  อายุ 70 ปี        444,000 บาท
  อายุ 80 ปี        671,000 บาท
  อายุ 99 ปี      1,112,000 บาท
```

สี่บรรทัดนี้ตอบว่า "ได้เท่าไร" แต่ไม่ตอบคำถามที่ลูกค้าถามจริงในห้องขาย —
**จ่ายไปเท่าไรแล้ว และเมื่อไรเงินที่ได้คืนถึงจะแซงเบี้ยที่จ่าย**

ข้อมูลที่ตอบได้มีอยู่ในเครื่องแล้ว `data/cash-values/lifeprotect.json` เก็บค่า
ต่อทุน 1,000 บาท รายปีกรมธรรม์ตั้งแต่ปีที่ 1 จนจบสัญญา ครบทั้งแปดรหัส
ชายและหญิง อายุแรกทำ 0 ถึง 80 ปี — 64 แถวสำหรับคนอายุ 35 แต่หน้าเว็บหยิบ
มาใช้สี่แถว

## สิ่งที่จะสร้าง

ต่อท้ายสี่บรรทัดเดิมในการ์ดผลลัพธ์ สองชิ้น

### หนึ่ง กราฟ

```
เบี้ยที่จ่าย เทียบกับ มูลค่าเงินสด

 1.1 ล้าน ┤                                    ╭─── มูลค่าเวนคืน (ทอง)
          │                        ╭───────────╯
          │            ╭───────────╯
          │      ╭─────╯      ●  เท่าทุนอายุ 59
          │  ╭───╯      ╭─────────────────────── เบี้ยสะสม (เทา)
        0 ┼──┴──────────┴────────────────────────
          35          59        70        80    99
```

เส้นทองคือมูลค่าเวนคืนเงินสด เส้นเทาคือเบี้ยที่จ่ายสะสม จุดที่เส้นทองแซง
เส้นเทาครั้งแรกมีจุดกลมและป้ายกำกับ "เท่าทุนอายุ 59"

วาดด้วย SVG ที่เขียนเอง ไม่ลงไลบรารีกราฟ โปรเจกต์นี้มี next, react,
supabase เท่านั้น และไม่มีงบเพิ่ม กราฟเส้นสองเส้นบนแกนเชิงเส้นไม่คุ้มกับ
ไลบรารีสี่สิบกิโลไบต์

### สอง ตารางทุกปี

ปุ่มพับ `<details>` ใต้กราฟ ปิดไว้ตอนเปิดหน้า

```

  ปีที่ │ อายุ │  คุ้มครอง │ เบี้ย/ปี │ เบี้ยสะสม │ เวนคืนได้
    1   │  35  │ 2,000,000 │  17,200 │    17,200 │         0
   ...
    9   │  43  │ 2,000,000 │  17,200 │   154,800 │    11,000
   ...
   25   │  59  │ 2,000,000 │  17,200 │   430,000 │   225,000
   26   │  60  │ 1,000,000 │  17,200 │   447,200 │   243,000
   ...
   64   │  98  │ 1,000,000 │  17,200 │ 1,100,800 │ 1,112,000   ← พื้นทอง

  ┃ ปีที่ 1–8 ยังไม่มีมูลค่าเวนคืน เบี้ยช่วงต้นถูกใช้ไปกับค่าใช้จ่ายในการ
  ┃ ออกกรมธรรม์ เป็นปกติของประกันตลอดชีพทุกบริษัท แบบนี้เน้นความคุ้มครอง
  ┃ ไม่ใช่การออมระยะสั้น

  แถวสุดท้าย (ปีที่ 64) คือเงินที่ได้รับเมื่อครบสัญญาอายุ 99 ปี
```

หกคอลัมน์พอดีจอกว้าง 375 จุดโดยไม่ต้องเลื่อนซ้ายขวา ตารางกินเต็มความกว้าง
การ์ด มีเส้นคั่นระหว่างคอลัมน์ และเว้นที่ขอบขวาให้แถบเลื่อนไม่ทับตัวเลข

คอลัมน์ที่สามคือความคุ้มครองของปีนั้น ไม่ใช่ทุนประกัน สองเลขนี้ต่างกันใน
แบบนี้ — ทุนคือ 1,000,000 ส่วน 2,000,000 คือสิ่งที่ครอบครัวได้รับเมื่อ
เสียชีวิตก่อนอายุ 60 หัวคอลัมน์จึงเป็น "คุ้มครอง" การเขียนว่า
"ทุนประกัน 2,000,000" จะขัดกับบล็อก "ครอบครัวได้รับเมื่อเสียชีวิต" ที่อยู่
เหนือขึ้นไปในการ์ดเดียวกัน และขัดกับกรมธรรม์ ส่วนบรรทัดสรุปเหนือตาราง
ยังบอกทุนประกันไว้ ทำให้ความต่างของสองคำอ่านออกในที่เดียวกัน

ปีที่พ้นกำหนดชำระแล้วในคอลัมน์เบี้ยต่อปีเป็นขีด ไม่ใช่คำว่า "ครบแล้ว"
หรือเลขศูนย์

หัวตารางติดขอบบนต้องมี `z-index` ไม่อย่างนั้นแถวที่เลื่อนผ่านจะทะลุขึ้นมา
ซ้อนทับตัวอักษรของหัวตาราง — พบตอนทำตัวอย่าง

## เรื่องที่ตัดสินใจไว้แล้ว

**เบี้ยสะสมนับจากเบี้ยรายปีเสมอ** แม้การ์ดจะพาดหัวเป็นราคารายเดือน ใต้กราฟ
เขียนกำกับว่า "เทียบจากเบี้ยรายปี"

เหตุผลคือตารางมูลค่ากรมธรรม์ในเล่มจริงคิดจากเบี้ยรายปี และการจ่ายรายงวด
มีค่าธรรมเนียมงวดทับอยู่ ตัวเลขจริงของชาย 35 ทุน 1 ล้าน แบบถึงอายุ 99

| นับจาก | เบี้ยต่อปีจริง | เท่าทุน |
| --- | --- | --- |
| รายปี 17,200 | 17,200 | ปีที่ 64 อายุ 98 |
| รายเดือน 1,548 | 18,576 | ไม่มีวันเท่าทุน |

ถ้าใช้งวดที่ลูกค้าเลือก แบบที่หน้าเปิดมาเป็นค่าตั้งต้นจะขึ้นกราฟที่เส้นทอง
ไม่แตะเส้นเทาเลยตลอดชีวิต ซึ่งจริงแต่ไม่ใช่เรื่องที่กราฟนี้ตั้งใจจะบอก
คำกำกับเป็นตัวแก้ ไม่ใช่การซ่อน

**แถวที่มูลค่าเป็นศูนย์แสดงตามจริง พร้อมคำอธิบายใต้ตาราง** ปีแรก ๆ
เวนคืนไม่ได้เลย และยาวกว่าที่คนส่วนใหญ่คิด จำนวนปีนับจากไฟล์ต้นฉบับ ชาย

| แบบชำระ | แรกเกิด | อายุ 20 | อายุ 35 | อายุ 50 |
| --- | --- | --- | --- | --- |
| จ่าย 9 ปี | 3 | 2 | 1 | 2 |
| จ่าย 19 ปี | 5 | 3 | 3 | 3 |
| ถึงอายุ 99 | 11 | 9 | 8 | 5 |

ยิ่งเบี้ยต่อปีถูก ยิ่งใช้เวลานานกว่าจะมีมูลค่าเวนคืน และแบบถึงอายุ 99 คือ
แบบที่หน้านี้เปิดมาเป็นค่าตั้งต้น

ศูนย์เหล่านี้เป็นเลข `0` ที่พิมพ์ไว้ในไฟล์ต้นฉบับจริง ไม่ใช่ช่องว่างที่
`int(v or 0)` ใน `extract_lifeprotect_cash_values()` แปลงเป็นศูนย์ — ตรวจ
เซลล์ดิบในชีต `TABCV(Male)` แล้ว ชาย 35 แบบ WLF99H อ่านได้
`0,0,0,0,0,0,0,0,11,23,35,48`

ใต้ตารางจึงมีคำอธิบายที่นับจำนวนปีเอง ขึ้นก่อนที่ลูกค้าจะทันสังเกต —
พูดก่อนถูกถามน่าเชื่อถือกว่าปล่อยให้เห็นเอง และเป็นประโยคที่เอเจนต์
หยิบไปพูดต่อได้ `cashValueHighlights` กรองศูนย์ทิ้งเพราะมันเลือกหมุดให้
สี่บรรทัด ตารางเต็มไม่กรอง

**อายุในตารางคืออายุต้นปีกรมธรรม์ จำนวนเงินคือปลายปีนั้น** ตามที่ตาราง
บริษัทกำกับไว้ และตรงกับสี่บรรทัดที่หน้านี้แสดงอยู่แล้ว — "อายุ 60 ปี
243,000 บาท" คือปีกรมธรรม์ที่ 26 ของคนที่ทำตอน 35

แถวสุดท้ายเป็นข้อยกเว้นที่ต้องระวัง ค่าตัวสุดท้ายในตารางบริษัทคือเงินที่ได้
ตอนครบสัญญา `maturityValue()` จึงติดป้ายมันว่า "อายุ 99" ทั้งที่เป็นปี
กรมธรรม์ที่เริ่มตอนอายุ 98 ตารางเต็มจึงไม่เพิ่มแถวครบสัญญาต่อท้าย —
แถวที่ 64 คือแถวนั้นอยู่แล้ว การเพิ่มจะกลายเป็นตัวเลขเดิมซ้ำสองแถว
แถวสุดท้ายกำกับว่า "ครบสัญญา อายุ 99" แทน จำนวนเงินจึงตรงกับบรรทัด
"อายุ 99 ปี" ข้างบนเป๊ะ

**ข้อมูลไปกับหน้า ไม่ยิงขอทีหลัง** ค่าต่อทุนพันของสามแบบชำระ สองเพศ
แปดสิบเอ็ดอายุ เป็น 111 กิโลไบต์ดิบ 28 กิโลไบต์หลังบีบอัด

ค่าทุกตัวคูณตรงตามทุนประกัน ลูกค้าลากสไลเดอร์ทุนจากห้าแสนไปห้าสิบล้าน
กราฟและตารางขยับทันทีโดยไม่ต้องขอข้อมูลใหม่ ถ้ายิงขอทีหลังจะต้องมีทั้ง
สถานะกำลังโหลด แคชฝั่งเบราว์เซอร์ และเส้นทางข้อมูลที่สอง ซึ่งเป็นโอกาส
ให้กราฟกับสี่บรรทัดข้างบนพูดไม่ตรงกัน

**หมุดสี่บรรทัดเดิมคำนวณจากตารางเต็ม ไม่ส่งซ้ำ** ตอนนี้ `LifeProtectTerm.cash`
ส่งเฉพาะหมุด 60/70/80/ครบสัญญา มาแยกต่างหาก เมื่อส่งตารางเต็มแล้ว หมุด
เป็นส่วนย่อยของมัน การส่งทั้งสองอย่างคือข้อมูลชุดเดียวสองทาง ซึ่งเพี้ยน
จากกันได้ `cash` ถูกแทนด้วย `schedule` และ `cashAt()` หยิบหมุดจาก
`schedule` แทน

**ความคุ้มครองไม่ได้ตายตัวที่ทุนประกัน** เชิงอรรถในเอกสารเสนอขายของบริษัท
เขียนไว้ว่า

> ผลประโยชน์กรณีเสียชีวิต บริษัทจะจ่ายผลประโยชน์กรณีเสียชีวิตตามข้อ * และ **
> ข้างต้น หรือเงินค่าเวนคืนกรมธรรม์ หรือร้อยละ 101 ของเบี้ยประกันภัยของ
> กรมธรรม์หลักที่ชำระมาแล้วทั้งหมด แล้วแต่จำนวนใดจะมากกว่า

และสูตรในชีต `ตารางแสดงผลประโยชน์` ก็ทำแบบนั้นจริง

```
H = IF(อายุ < 60, MAX(200% × ทุน, 101% × เบี้ยสะสม, มูลค่าเวนคืน),
                  MAX(100% × ทุน, 101% × เบี้ยสะสม, มูลค่าเวนคืน))
```

คอลัมน์คุ้มครองและเส้นประบนกราฟจึงต้องยกตาม ไม่ใช่ราบอยู่ที่ทุนประกัน
มิฉะนั้นหน้าเว็บจะบอกความคุ้มครองต่ำกว่าที่กรมธรรม์จ่ายจริง ชาย 35
ทุน 1 ล้าน แบบถึงอายุ 99 เริ่มยกตั้งแต่ปีที่ 58

| ปีที่ | อายุ | เบี้ยสะสม | เวนคืนได้ | คุ้มครอง |
| --- | --- | --- | --- | --- |
| 57 | 91 | 980,400 | 879,000 | 1,000,000 |
| 58 | 92 | 997,600 | 905,000 | 1,007,576 |
| 59 | 93 | 1,014,800 | 932,000 | 1,024,948 |
| 64 | 98 | 1,100,800 | 1,112,000 | 1,112,000 |

ผลพลอยได้คือเบี้ยสะสมไม่มีวันแซงความคุ้มครอง กรณีที่น่ากังวลจึงไม่เกิดขึ้น
จริงตั้งแต่แรก

เส้นกริดบนกราฟยังปักที่ **ทุนประกัน** ไม่ใช่ค่าคุ้มครองแถวสุดท้าย เพราะทุน
คือเลขที่ลูกค้าเลือกเอง `Projection.coverFloor` ถือค่านั้นไว้ให้

## ของที่ไม่ทำ

**มูลค่าใช้เงินสำเร็จ และมูลค่าขยายเวลา** ตารางมูลค่ากรมธรรม์ในเล่มจริงมี
สามช่อง ไฟล์ที่สกัดไว้มีช่องเดียวคือมูลค่าเวนคืนเงินสด
`Sales proposal_Life Protect Plus 9 19 99_2026821_update benefit graph.xlsx`
ไม่มีอีกสองช่อง ต้องได้ไฟล์ต้นทางอีกใบก่อนถึงจะทำได้ หน้าเว็บจึงเรียกสิ่งนี้
ว่า "มูลค่าเงินสด" ไม่ใช่ "ตารางมูลค่ากรมธรรม์" เพื่อไม่ให้ลูกค้าเข้าใจว่า
เห็นครบแล้ว

**หน้า `/legacy` และเครื่องคำนวณที่ `/`** ไม่แตะ

**การ์ดรูปที่ `/api/card`** ไม่แตะ ตารางหกสิบสี่แถวไม่ลงการ์ดที่ส่งในแชท

## โครงสร้าง

ไฟล์ใหม่สามใบ

`src/lib/cash-projection.ts` — ฟังก์ชันล้วน ไม่รู้จัก React

```ts
/** ทุกจำนวนเงินเป็นสตางค์ ตามที่ calc/money.ts ทั้งไฟล์ทำงาน */
interface ProjectionRow {
  policyYear: number;
  age: number;                 // อายุต้นปีกรมธรรม์
  cover: number;               // ครอบครัวได้รับถ้าเสียชีวิตปีนั้น
  premiumDue: number | null;   // เบี้ยของปีนั้น; 0 เมื่อพ้นกำหนดชำระ
  premiumPaid: number | null;  // สะสม; null เมื่อไม่มีราคาให้แสดง
  cashValue: number;           // ปลายปีนั้น
}
interface Projection {
  rows: ProjectionRow[];
  breakEven: ProjectionRow | null;  // แถวแรกที่ cashValue >= premiumPaid
  zeroYears: number;                // จำนวนปีต้นที่ยังไม่มีมูลค่าเวนคืน
  maturityAge: number;              // อายุที่แถวสุดท้ายหมายถึง
}
interface ProjectionInput {
  factors: number[]; age: number; sumAssured: number;
  annualSatang: number | null; payYears: number; death: DeathBenefit;
}
cashProjection(input: ProjectionInput): Projection
```

ตารางเบี้ยหมดอายุ `table.expired` เป็นจริง หน้านี้ห้ามแสดงราคา
`annualPremium` เป็น null กราฟเหลือเส้นทองเส้นเดียว ตารางเหลือสามช่อง
ไม่มีช่องเบี้ยสะสม ไม่มีจุดเท่าทุน มูลค่าเวนคืนไม่ใช่ราคา จึงแสดงได้

อายุที่เลือกไม่มีตารางมูลค่า `schedule` เป็น null ทั้งกราฟและตารางหายไป
เหมือนที่สี่บรรทัดเดิมหายไปอยู่แล้ว
