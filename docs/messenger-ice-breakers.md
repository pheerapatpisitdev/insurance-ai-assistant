# ปุ่มต้อนรับของเพจ กับปุ่มในโฆษณา ต้องพูดภาษาเดียวกับบอท

ปุ่มต้อนรับ (ice breakers) ไม่ได้อยู่ในโค้ดของโปรเจกต์นี้ — ตั้งไว้บนเพจ Facebook โดยตรง
(แอปเคยจัดการให้ แล้วถอดออกตอน Meta เปลี่ยน API) ส่วนปุ่มในข้อความต้อนรับของโฆษณา
ตั้งอยู่ใน Ads Manager ของโฆษณาแต่ละตัว

ที่ต้องจดไว้คือ **ปุ่มพวกนี้ไม่ได้ส่งรหัสอะไรมาให้บอทเลย — ส่งมาแค่ชื่อปุ่มของตัวเอง**
บอทอ่านชื่อปุ่มเป็นข้อความธรรมดา แล้วเดาแบบประกันจากคำในนั้น
([`textOf`](../src/lib/facebook/events.ts) อ่าน `postback.title` หรือ `payload`
แล้วส่งต่อให้ [`productNamedIn`](../src/lib/assistant/choose.ts))

เพราะฉะนั้น **ปุ่มที่ใช้คำที่บอทไม่รู้จัก = ลูกค้าที่กดแล้วโดนถามกลับว่า "สนใจแบบไหนครับ"**
ซึ่งเป็นการถามคนที่เพิ่งตอบไปแล้ว

## ชุดคำที่ใช้อยู่ (18 ก.ย. 2569)

ทั้งเพจ **LuckyPlanner** (105982528649026) และ **ประกัน Talk** (1431905706931225)
ตั้งไว้ตรงกัน และตรงกับปุ่มในโฆษณาที่กำลังยิงอยู่

| ปุ่ม | บอทพาไป |
| --- | --- |
| สนใจมรดก เบี้ยไม่ทิ้ง ได้เงินคืน | `lifeprotect` (คำที่จับคือ "เบี้ยไม่ทิ้ง") |
| สนใจมรดก เบี้ยทิ้ง + โรคร้ายแรง | `legacy` (คำที่จับคือ "เบี้ยทิ้ง") |
| สนใจมรดก + ออม + โรคร้ายแรง | `ishield` (คำที่จับคือ "ออม") |
| สนใจประกันสุขภาพ ค่าห้องค่ารักษา | `ihealthy` (คำที่จับคือ "ประกันสุขภาพ") |

## ก่อนจะเปลี่ยนคำบนปุ่ม

1. เปิด [`src/lib/assistant/choose.ts`](../src/lib/assistant/choose.ts) ดู `NAMES`
   ว่าคำใหม่มีอยู่ในรายการไหน
2. คำใหม่ต้องตรงกับ **แบบเดียว** เท่านั้น ถ้าตรงสองแบบพร้อมกัน `productNamedIn` จะคืนค่าว่าง
   แล้วลูกค้าจะได้เมนูแทนคำตอบ — เช่น "มรดก + ออม + โรคร้ายแรง" ตั้งใจเขียนให้ไม่ชน
   กับรูปแบบ `มรดก + โรคร้าย` ของ legacy
3. ปุ่มของ Messenger ตัดข้อความที่ยาวเกิน 20 ตัวอักษรโดยไม่บอก — แต่ข้อจำกัดนั้นเป็นของ
   ปุ่มตอบกลับ (quick reply) ที่บอทส่งเอง ปุ่มต้อนรับยาวได้ถึง 80 ตัวอักษร

## คำที่เคยใช้ แล้วเลิกใช้

ปุ่มต้อนรับชุดเดิมของ LuckyPlanner คือ "สนใจประกันมรดก ขอรายละเอียด",
"มรดก 3 ล้าน เบี้ยเท่าไหร่", "มรดก 5 ล้าน เบี้ยเท่าไหร่", "ประกันมรดก คุ้มครองอะไรบ้าง"

สองข้อแรกและข้อสุดท้ายไม่มีคำที่บอทแยกแบบประกันได้ — "ประกันมรดก" เฉย ๆ ไม่ตรงกับแบบไหน
ส่วน "มรดก 3 ล้าน เบี้ยเท่าไหร่" ตัวเลข "ล้าน" ทำให้ถูกอ่านเป็น `lifeprotect`
ทั้งที่ทุนขนาดนั้นแบบเบี้ยทิ้ง + โรคร้ายแรงเบากว่ามาก จึงเปลี่ยนมาใช้ชุดเดียวกับโฆษณา

## อ่านหรือเปลี่ยนด้วยมือ

โทเคนเพจเก็บเข้ารหัสอยู่ใน `ins_channel_auth` อ่านผ่าน RPC `ins_get_channel_auth`
(ต้องใช้ service role key กับ `ADMIN_SESSION_SECRET` เป็น passphrase) แล้วเรียก

```
GET  https://graph.facebook.com/v23.0/me/messenger_profile?fields=ice_breakers
POST https://graph.facebook.com/v23.0/me/messenger_profile
     {"ice_breakers":[{"locale":"default","call_to_actions":[{"question":"…","payload":"…"}]}]}
```

`payload` ตั้งให้เหมือน `question` ไปเลย เพราะบอทอ่านคำ ไม่ได้อ่านรหัส
